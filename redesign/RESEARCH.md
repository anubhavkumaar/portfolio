# Shift the portfolio from spectacle to proof

The redesign of anubhavkumaar.in should keep its connected scroll and its glass-and-light look, but move the effort from decorative motion to proof. Make the intro loader skippable, once per session and never shown on deep links. Rebuild the section exits on native CSS scroll timelines. Turn the fast 3D sphere into a scroll-scrubbed, reversible sequence with a cheaper phone variant. Morph Work covers into case-study heroes with Next.js `<ViewTransition>`. Spend the generation budget on sanitized animated architecture diagrams and one signature hero loop rather than more ambient AI video. This matters because **80% of recruiters spend 3 minutes or less on a portfolio** and skim past most case-study text ([UX Collective](https://uxdesign.cc/ever-wonder-how-recruiters-look-at-your-design-portfolio-cc8dd1ecb698)), so the first viewport, the resume link and a TL;DR per project do more for hiring outcomes than any shader. The platform has also caught up: CSS scroll-driven animations reached Baseline in October 2026 ([web.dev](https://web.dev/blog/web-platform-10-2026?hl=en)) and Next.js now ships view transitions with no configuration ([Next.js](https://nextjs.org/docs/app/guides/view-transitions)), so a lot of custom JS can simply be deleted. On a 390x844 phone, every hover, 3D and video effect needs a cheaper twin, because iOS 26 Safari clips fixed bottom UI and Low Power Mode blocks even muted autoplay. One deadline matters: Veo 3.1 Fast and Quality retire in Flow on **December 5, 2026**, so batch any Veo work before then ([Google Labs Help](https://support.google.com/labs/answer/16526234?hl=en)).

## Native scroll timelines now carry the connected scroll

The cleanest 2026 stack for this site is native scroll plus three layers, each doing one job. CSS `view()` timelines handle the per-section exit (the shrink and fade as Home, Work, About and Connect leave). Motion's `useScroll` handles anything that must also feed React or WebGL state, such as the sphere-to-drawer progress or a shader uniform. Motion's `whileInView` handles the intro replay on re-entry. Motion runs its scroll-linked values on the browser's native `ScrollTimeline` where it can and falls back to JS otherwise, while `whileInView` uses a pooled IntersectionObserver ([Motion](https://motion.dev/docs/react-scroll-animations)). GSAP is now free in full, including ScrollTrigger, Flip and a rewritten SplitText that is 50% smaller and adds masked line reveals, `autoSplit` re-splitting on font load and automatic `aria-label` handling ([GSAP 3.13](https://gsap.com/blog/3-13/)). Even so, it is worth adding only if a pinned timeline becomes too complex for Motion. Running Lenis, Motion `useScroll` and ScrollTrigger together is the setup to avoid.

**Browser support has one open conflict.** web.dev's October 2026 roundup reports that **Firefox 159 turned scroll-driven animations on by default**, which makes them Baseline Newly available alongside Chrome 115, Edge 115 and Safari 26 ([web.dev](https://web.dev/blog/web-platform-10-2026?hl=en)). A July 2026 article still listed Firefox 152 with the feature behind `layout.css.scroll-driven-animations.enabled` and put global support at about 82.6% ([buildmvpfast](https://www.buildmvpfast.com/blog/css-scroll-driven-animations-replace-js-2026)). The newer source should win. Still, Firefox 159 is weeks old and plenty of visitors will be on older versions, so treat the feature as progressive enhancement. The recipe is to wrap everything in `@media (prefers-reduced-motion: no-preference) { @supports (animation-timeline: view()) { ... } }` and keep the fully visible state as the default, so an unsupported browser never gets stuck at `opacity: 0`. Use `animation-range: entry 0% cover 40%` for intros, `animation-duration: auto`, and `scroll(root block)` if a nested scroller might capture the timeline ([buildmvpfast](https://www.buildmvpfast.com/blog/css-scroll-driven-animations-replace-js-2026)). For the outgoing section, map `animation-range: exit 0% exit 100%` to roughly `scale(0.94)` plus a fade. The replay-on-re-entry behaviour then becomes `whileInView` with `viewport={{ once: false, amount: 0.4 }}`. Chrome 146 added native scroll-triggered animations (`timeline-trigger`, `animation-trigger: --t play-forwards play-backwards`) that would do this in pure CSS, but only Chrome is reported to support them ([lilting.ch](https://lilting.ch/en/articles/chrome-146-scroll-animation-safari-grid-lanes)), so they are an enhancement and not the base.

**Lenis is now optional, and desktop-only if kept.** Version 1.3.27 defaults to `lerp 0.1`, `syncTouch: false` and `respectReducedMotion: true` (which forces `lerp: 1`), and it keeps native scroll underneath so sticky positioning and anchors still work. The costs are real, though: it is capped at 60fps on Safari and 30fps in Low Power Mode, it does not support CSS scroll-snap, and `allowNestedScroll` checks the DOM on every scroll event ([Lenis](https://github.com/darkroomengineering/lenis)). Keep it only if the smoke shader must be synced to scroll every frame, at `lerp` 0.08 to 0.1, and only when `(pointer: fine)` matches and reduced motion is off.

**The 3D sphere should be scrubbed, not timed.** Rather than a fast, time-based flight of 20 covers into the drawer, wrap the sequence in a 200 to 300vh section with a sticky inner viewport. Drive its progress from `useScroll({ target, offset: ["start start", "end end"] })`, using the tall-container-plus-sticky pattern Motion documents for horizontal galleries, where a taller container gives a slower feel ([Motion](https://motion.dev/docs/react-scroll-animations)). That makes the moment reversible, readable and far less of a vestibular risk. Inside the page, Motion `layoutId` stays the right tool for sphere cover to drawer folder, drawer to freestyle, and the hover info card, since no route change happens there. For a card that appears from `display: none`, CSS `@starting-style` with `transition-behavior: allow-discrete` is the native option ([Chrome for Developers](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/motion)).

**Route changes belong to View Transitions, not AnimatePresence.** Exit animations do not work in the App Router, and the FrozenRouter workaround depends on undocumented internals that are not safe under concurrent rendering ([vercel/next.js #42658](https://www.github.com/vercel/next.js/discussions/42658)). Next.js now supports `<ViewTransition>` with no configuration on React 19.3. Wrap each Work cover and its case-study hero in `<ViewTransition name={`cover-${slug}`} share="morph" default="none">` and set `::view-transition-group(.morph) { animation-duration: 400ms }`, with a `filter: blur(3px)` at 30% to hide interpolation artifacts. The morph only pairs when the destination renders in the same commit, so the case-study routes have to be statically generated and prefetched. Directional navigation uses `transitionTypes={['nav-forward']}` on `<Link>`, and the documented timings are a 150ms ease-in exit fade plus a 400ms slide, a 210ms enter fade delayed 150ms, and a 60px offset. Pin the header with `view-transition-name: site-header` and `animation: none`, and add `::view-transition { pointer-events: none; }` so clicks are not swallowed ([Next.js](https://nextjs.org/docs/app/guides/view-transitions)). The same pinning should apply to the smoke background: mount it in the root layout outside `{children}` so it never remounts during a transition. One caveat is that browser back and swipe-back carry no transition type, so directional slides will not play on them, although morphs still will ([Next.js](https://nextjs.org/docs/app/guides/view-transitions)).

**URL-per-section should use `history.replaceState`, never `router.replace`.** Next.js officially folds native `pushState` and `replaceState` into the router, so `usePathname` updates without a navigation ([Next.js](https://nextjs.org/docs/app/building-your-application/routing/linking-and-navigating)). `router.replace` would trigger an RSC navigation and a scroll to top. Make `/work`, `/about` and `/connect` real `page.tsx` routes that render the same one-page layout with an initial scroll target and their own `metadata`, so refresh, sharing and SEO all work. On a direct load, call `scrollIntoView({ behavior: 'instant' })` before the intros run and hold off the URL observer until the page settles, so it does not write `/` first. Use `scroll-padding-top` to clear the fixed bar. Restoring scroll position when returning from a case study to a rewritten path is not documented anywhere and needs testing.

**Performance and accessibility rules are specific.** Animate only `transform` and `opacity`, adding `filter` and `clip-path` sparingly. Keep about 10 to 20 scroll-linked elements live at once, and load Motion through `LazyMotion` with `domAnimation` (about 15kB gzip against about 35kB for the full bundle), per a secondary mirror of Motion's docs ([Mintlify mirror](https://www.mintlify.com/motiondivision/motion/guides/performance)). Chrome's guidance is to implement reduced motion as "remove spatial movement, keep fades", not as a global `animation-duration: 0.01ms`, and to check `element.getAnimations()` because `animationend` never fires when an animation is suppressed ([Chrome for Developers](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/motion)). For view transitions, zero out `::view-transition-old/new/group(*)` durations under `prefers-reduced-motion: reduce`, since directional slides are the biggest vestibular trigger ([Next.js](https://nextjs.org/docs/app/guides/view-transitions)). **WCAG 2.2.2 applies to two current elements.** The smoke loop auto-runs for more than 5 seconds alongside content, and the cycling "I am a..." line counts as auto-updating content, which gets no 5 second exception. Both need a pause, a stop, or a static state ([W3C](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide)).

## Diagrams earn more than another AI glow loop

The site already has plenty of decorative AI motion: the Veo neural-sphere loader, a supervisor-agent loop and the WebGL smoke. What it lacks is visuals that explain engineering. The highest-value additions are one animated architecture or pipeline diagram per case study, plus one or two stylized UI shots built on fake data. Ambient generated video should stop at one signature hero loop and at most one other loop, because **autoplaying video starts downloading immediately, even off screen**, and in Chromium a video's first frame can become the LCP element ([web.dev](https://web.dev/learn/performance/video-performance)). Labeled diagrams should not come from diffusion models at all, since they still mangle text. Author them as inline SVG with stroke-dash pulses, or as Rive when they need to be interactive. Rive's state machines and data binding can, for example, highlight a node's edges on hover, and the vendor reports files 10 to 15x smaller than equivalent Lottie JSON (a 240 KB Lottie recreated at 16 KB) ([Rive](https://rive.app/blog/rive-as-a-lottie-alternative)). The same source warns that Lottie's blur and drop shadows are expensive on mobile, which is exactly what a glass-and-light style relies on. The practical rule: glow-heavy motion goes to video or a shader, and flat-line diagram motion goes to SVG, Rive or dotLottie. Two inventory gaps are easy to miss. Only 16 covers exist for 20 projects, so four need generating, and each project needs a 1200x630 Open Graph card.

**Confidentiality has to be built into the asset pipeline, not checked at the end.** Every case-study visual should use generic component names (Supervisor, Retriever, Vector Store, Tool Server A), fake seeded data in UI mocks, no client or state names, no internal hostnames, no real schemas or code, and no client iconography. The safest way to get "UI screens" is to build a small fake dashboard in the site's own React stack, screenshot it, and set it in an AI-generated glass device frame.

### Tool choice depends on budget, watermarks and loops

Google now meters the Gemini app on a compute pool that "refreshes every 5 hours until you reach your weekly limit", and video uses up the most of it ([Gemini Help](https://support.google.com/gemini/answer/16275805)). That explains running out after a handful of clips. Flow has a separate, predictable credit budget. AI Pro adds 1,000 credits a month (no rollover). A Veo 3.1 Lite clip costs 10 credits (720p, 4, 6 or 8 s), Fast costs 20, and Quality costs 100 (8 s only). Upscaling to 1080p is free for 1 to 10 s clips, while 4K upscaling is Ultra-only at 50 credits. Veo 3.1 Fast and Quality retire on December 5, 2026, after which the newer Omni Flash 1.2 runs up to 10 s at 3 credits per second for 720p ([Google Labs Help](https://support.google.com/labs/answer/16526234?hl=en)). On AI Pro that works out to about 50 Fast or 10 Quality clips a month, so iterate on Lite or Fast and spend Quality only on the final hero take.

**Watermarks are the hidden constraint for a professional site in India.** Google's August 2026 "Media Watermarks" toggle only removes visible marks in India on AI Ultra, and SynthID plus C2PA metadata are always embedded regardless ([Digital Trends](https://www.digitaltrends.com/computing/googles-gemini-app-adds-a-toggle-to-disable-ai-watermarks-with-some-exceptions/)). Whether Flow output carries a visible mark on AI Pro could not be confirmed, so check the corner of every export. Do not crop marks out, since that may breach provider terms. Adobe Firefly is the cleanest commercial option: its own video model is marketed as "safe for commercial use", it exports MP4 up to 4K, it takes a first-frame image, and it hosts Veo 3.1, Runway Gen-4.5, Kling 3.0 and Luma Ray3 as partner models (which "may have different usage terms") ([Adobe](https://www.adobe.com/products/firefly/features/ai-video-generator)). For true loops, **Luma Ray 3.2 has a native seamless loop mode, but only for 5 s clips**, and it accepts up to four reference images to lock style ([Artlist Help](https://help.artlist.io/hc/en-us/articles/38170367259933-Luma-Ray-3-2)). A February 2026 comparison lists Kling 3.0 at up to 15 s, Sora 2 at up to 25 s and Runway Gen-4.5 at up to 10 s ([AdCreate](https://adcreate.com/blog/best-ai-video-models-february-2026-comparison)), but it says nothing on licensing, so check each provider's terms before shipping. A one-line footer note such as "Visuals generated with Gemini and Firefly" is honest, and it fits the provenance metadata that is embedded anyway.

### One style block, image first, then animate

Keeping assets consistent across tools comes from fixing everything except the subject. Paste the same style block into every prompt, use the two or three best existing covers as style references, generate the still first, and then animate it as the first frame. Run every output through one shared color grade and grain pass, and keep a prompt log (prompt, model, references, date) so variants can be regenerated after limits reset.

No text, no letters, no numbers, no logos, no people, no watermarks.

### Delivery specs: AV1 first, H.264 always, poster designed

Source order sets the browser's priority, so list the most efficient codec first and H.264 last ([web.dev](https://web.dev/learn/performance/video-performance)). The H.264 fallback is mandatory. **iPhones before the A17 Pro cannot decode AV1 at all, and Apple does not software-decode it**, so an iPhone 13 mini shows a broken player unless the `type` carries a codecs string that lets Safari skip the AV1 source ([alexwlchan](https://alexwlchan.net/2025/av1-on-my-iphone/)). caniuse puts AV1 at about 96% globally but marks Safari 17+ as only partial ([caniuse](https://caniuse.com/av1?ref=hopp)). Only the hero should autoplay. Below-the-fold loops should use `data-src` and an IntersectionObserver with a rootMargin of about 200px that calls `load()` then `play()`, and pauses when the loop leaves view. If the poster is the LCP element, preload it with `fetchpriority="high"`, but that hurts when it is not ([web.dev](https://web.dev/learn/performance/video-performance)). Any YouTube demo needs a click-to-load facade, since third-party embeds block the main thread for more than 1.7 s on the median site ([web.dev](https://web.dev/learn/performance/video-performance)).

```html
<video autoplay muted loop playsinline preload="metadata"
       poster="/media/hero-poster.avif" aria-hidden="true"
       disablepictureinpicture disableremoteplayback>
  <source src="/media/hero.av1.mp4"  type='video/mp4; codecs="av01.0.08M.08"'>
  <source src="/media/hero.vp9.webm" type='video/webm; codecs="vp9"'>
  <source src="/media/hero.h264.mp4" type='video/mp4; codecs="avc1.640028"'>
</video>
```

```bash
ffmpeg -i in.mp4 -an -c:v libsvtav1 -crf 38 -preset 6 -g 240 -pix_fmt yuv420p10le hero.av1.mp4
ffmpeg -i in.mp4 -an -c:v libx264 -crf 26 -preset slow -profile:v high -pix_fmt yuv420p -movflags +faststart hero.h264.mp4
ffmpeg -i in.mp4 -an -c:v libvpx-vp9 -crf 36 -b:v 0 -row-mt 1 hero.vp9.webm
```

The size targets below are practitioner rules of thumb rather than sourced benchmarks, but they give the build a budget to enforce. Ten-bit AV1 and a touch of added grain reduce banding on the dark navy gradients.

## Flows should win the three-minute skim first

The hiring evidence is older and comes from design portfolios, but it points one way. **80% of recruiters spend 3 minutes or less, 54% of design managers spend 5 to 10 minutes**, a reviewer scrolled past about 90% of case-study content, and **66% of recruiters source primarily on LinkedIn** ([UX Collective](https://uxdesign.cc/ever-wonder-how-recruiters-look-at-your-design-portfolio-cc8dd1ecb698)). A 2021 survey of React hiring managers found most do look at personal sites, and comments flagged broken links and poor maintenance ([Profy.dev](https://dev.to/profydev/this-survey-among-60-hiring-managers-reveals-don-t-waste-your-time-on-a-react-portfolio-website-17ge)). So the site has to work as a 60 to 180 second skim first and a deep read second. Today an intro video and a cycling role line come before any proof. The first viewport should state the role in plain words (for example, "GenAI engineer: agents, MCP tools, RAG in production"), carry two proof signals, and offer two actions: a stable `/resume.pdf` link and "Let's talk". That mirrors the "View Full Résumé" link on one of the most-copied engineer portfolios ([brittanychiang.com](https://brittanychiang.com/)). The role cycler should settle on the primary role after one pass, pause on hover and focus, render static under reduced motion, use `aria-live="off"`, and expose the full role list as visually hidden text.

**The intro loader is the costliest second on the site.** A 2016 test found that a 2 s loader plus a 1 s fade pushed "visually complete" from 1.3 s to 3.5 s, and advised never delaying the logo, tagline or navigation ([xfive](https://www.xfive.co/blog/intro-animations-perceived-performance)). Opquast's rule 127 requires a direct link past any splash ([Opquast](https://checklists.opquast.com/en/web-quality-assurance/the-course-of-video-or-any-animation-does-not-block-access-to-navigation-or-content)). WCAG exempts a loader only when it is shown alone ([W3C](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide)). Cap it at 2 to 3 s, play it once per session through `sessionStorage`, render the top bar from the first frame with a visible Skip, and skip it entirely under reduced motion, on return visits and on any deep link. A recruiter arriving from LinkedIn on a case-study URL should never see it.

**Work needs one default view, not three equal ones.** With 20 projects behind a drawer, a freestyle grid and an Index, a skimmer gets choice paralysis. Make 3 to 4 featured projects with one-line outcomes the default. Keep drawer and freestyle as a toggle persisted in the URL (`?view=drawer`) so back, forward and shared links restore it. Make the Index the canonical full list: a sortable, filterable table by year, type (agent, RAG, full-stack, tool), stack, status and a confidential flag, on the featured-plus-archive model ([brittanychiang.com](https://brittanychiang.com/)). Cursor-following thumbnail previews on project lists are a mainstream award-site pattern ([Awwwards](https://www.awwwards.com/inspiration/work-project-hovering-kkpk)). Enable them only under `(hover: hover) and (pointer: fine)` and turn them off under reduced motion. Every case study should end with next and previous project links that cycle within the view the visitor came from, plus left and right arrow keys.

**Every case study should share one TL;DR card and one section order, even when layouts vary.** Managers want a clearly stated problem, alternatives explored and an understandable walkthrough. Portfolios that repeat header, paragraph, image read "like an outline rather than a story", and the recommended fix is a summary on top with the story below ([UX Collective](https://uxdesign.cc/ever-wonder-how-recruiters-look-at-your-design-portfolio-cc8dd1ecb698)). The card should hold the one-line problem, role, stack chips, timeline, two or three rounded outcome metrics and status. Then come context and constraints, the re-drawn generic architecture diagram, two to four "chose X over Y because Z" decision blocks, outcomes and a reflection. For enterprise and public-sector work, the established tactics are to describe the work in general terms, list responsibilities and department, show process artifacts, and link a short confidentiality note from a badge ([van Schneider](https://vanschneider.com/blog/portfolio-tips/make-portfolio-work-cant-shared/)). Here that means a "Confidential: details generalized" badge, clients described no more specifically than "US state agencies", a demo recreated on synthetic data, and a "Deeper walkthrough available in interview" CTA routed to Let's talk.

**"Ask Anubhav" is the strongest work sample on the site, so treat it as a product.** A published portfolio RAG bot shows the guardrails worth copying: "Answer questions using only the provided context", "Do not make up information", temperature 0.3, top-8 chunks typed by source, the last 10 messages as history, and sub-500 ms responses ([DEV](https://dev.to/akromdev/i-built-an-ai-chatbot-that-knows-everything-about-me-4jeb)). Add three or four recruiter prompt chips ("What has he shipped with agents?", "Is he open to roles?", "Summarize his RAG work", "Get his resume"). Have answers cite and deep-link case-study routes. Add tool actions (open project, copy email, download resume) that show agent and MCP skill directly. Add a confidentiality guard, rate limiting and a "How this works" link to a case study of the bot itself. A Cmd/Ctrl+K palette built on cmdk, an unstyled, composable React command menu ([awesome-command-palette](https://www.github.com/stefanjudis/awesome-command-palette)), suits a developer audience: go to project, copy email, download resume, toggle theme, ask Anubhav. Show a small ⌘K hint in the top bar.

**Microinteractions should be small and tied to actions.** Josh Comeau's "boop" pattern applies a brief hover transform that resets even if the cursor stays, and he recommends that sounds play only on direct actions, come in several variants, stay off by default behind a persisted, keyboard-reachable mute, and never carry information alone ([Whimsical Animations](https://joshwcomeau.com/blog/whimsical-animations), [use-sound](https://joshwcomeau.com/react/announcing-use-sound-react-hook/)). Concretely: a copy-email button with a toast and an `aria-live="polite"` announcement as the primary contact path, with mailto and LinkedIn alongside. "Let's talk" opens a small menu (copy email, LinkedIn, resume, Ask Anubhav). Buttons get a 0.97 press scale. A scroll hint fades after the first scroll. The 404 page offers the palette and the featured projects. The accessibility baseline is a skip link as the first focusable element ([brittanychiang.com](https://brittanychiang.com/)), visible `:focus-visible` rings in both themes, every drawer and grid item openable with Enter, and Escape returning focus to the trigger. Fully immersive 3D is the cautionary tale here: Bruno Simon's earlier portfolio scored 8.60 for animations on Awwwards but only 6.60 for accessibility ([Awwwards](https://www.awwwards.com/sites/brunos-portfolio)), and users of his 2025 version reported loader delays, tab freezes and broken iOS touch controls ([GeekNews](https://news.hada.io/topic?id=24963)). The site's current 2D restraint is the better fit for a hiring audience.

## On a 390x844 phone, every desktop effect needs a cheaper twin

**Keep navigation at the top.** iOS 26 Safari's Liquid Glass toolbar reserves space at the bottom. Safari will not render `position: fixed` or `sticky` content below its bottom controls, so fixed content "is effectively unable to reach the bottom of the page" ([Apple Developer Forums](https://developer.apple.com/forums/thread/800798)). Fixed bottom elements end up sitting higher than expected ([medienbaecker](https://medienbaecker.com/articles/the-web-behind-glass)). A bottom tab bar would fight the browser chrome. The better pattern is a fixed top bar of about 56px (logo, current-section label, and a Menu button with at least a 44x44 hit area) that opens a full-height sheet with the four section links set in the lower half, where thumbs reach. Safari also samples page colours to tint its toolbar. Frequent light and dark switches produced toolbar contrast as low as 1.59 to 2.44 in testing, so keep one dominant near-black background across Home, Work, About, Connect and the case studies ([medienbaecker](https://medienbaecker.com/articles/the-web-behind-glass)). The smoke aesthetic already suits that.

**Scroll stays native on touch.** Create Lenis only when `(pointer: coarse)` does not match and reduced motion is off. WebKit's own guide recommends gating scroll-driven animations with `@media not (prefers-reduced-motion)` and warns that large zoom-like motion during fast scrolling causes discomfort ([WebKit](https://www.webkit.org/blog/17101/a-guide-to-scroll-driven-animations-with-just-css/)), so keep the phone exit at a gentle `scale(0.94)` plus a fade. Use `100svh` for hero and section heights so the collapsing address bar does not shift layout. Reserve `100dvh` for the menu sheet, and never animate against `dvh` during scroll. Add `overscroll-behavior-y: none` on the sheet and any inner scroller, and avoid mandatory scroll-snap on the main page. For the URL observer on phones, use a centre band of `rootMargin: '-45% 0px -45% 0px'` and debounce about 150ms so momentum flicks do not thrash `replaceState`.

|---|---|---|
| Top bar plus inline links | Top bar plus full-height menu sheet, links in the lower half | 56px bar, 44x44 Menu, `padding-top: env(safe-area-inset-top)` |

**Hover has to become position or tap.** Gate every hover style with `@media (hover: hover) and (pointer: fine)`, and pass Motion's `whileHover` only when that query matches, so iOS's sticky emulated hover does not leave cards stuck lifted. Motion's tap gestures are keyboard-accessible by default: any element with a tap prop becomes focusable and responds to Enter ([Motion](https://motion.dev/docs/react-gestures)). Avoid long-press as the only path, since it collides with iOS link previews. Stretching a card's link over the whole card enlarges the target but makes its text harder to select ([Ahmad Shadeed](https://ishadeed.com/article/target-size/)), so use that sparingly.

**The sphere is the riskiest element on low-end Android.** A 20-face `preserve-3d` sphere creates 20 or more composited layers. Tier it by `deviceMemory`, `hardwareConcurrency`, save-data and a one-second rAF sample after load, dropping to the carousel if the median frame exceeds about 20ms. Do the fly-into-drawer step as a FLIP of transforms, add `will-change` only while animating, and never stack `backdrop-filter`, `filter: blur()` and `mix-blend-mode` over the smoke video. Bake blur into the assets instead. Lenis's documented 30fps cap in Low Power Mode ([Lenis](https://cdn.jsdelivr.net/npm/lenis@1.3.18/README.md)) hints that iOS throttles every rAF-driven animation, so the sphere has to look acceptable at 30fps too. These tier thresholds are judgment calls, and no benchmark for layer counts on specific devices was found.

**Low Power Mode blocks muted inline autoplay, by design.** On iOS, `play()` rejects with `NotAllowedError` even for muted `playsinline` video, and WebKit maintainers call this "desirable" ([WebKit bug 216887](https://bugs.webkit.org/show_bug.cgi?id=216887)). Every video therefore needs a poster that looks finished on its own, plus `video.play().catch(() => el.classList.add('is-poster'))`. For data saving, `prefers-reduced-data` has no shipping support (the source is from 2021, so re-check). The usable signals are `navigator.connection.saveData` and `effectiveType` in Chromium and the `Save-Data` request header, which Next.js middleware can read to serve lighter variants ([Polypane](https://polypane.app/blog/creating-websites-with-prefers-reduced-data)). When either is set, skip the smoke and intro videos in favour of posters and load covers at 1x.

**Touch, type and safe areas follow fixed numbers.** Use 44x44 CSS px as the floor (WCAG 2.5.5 AAA) and 48x48 where space allows (Material). 24x24 is only the WCAG 2.5.8 AA minimum. Put padding on the link itself, for example `padding: 0.75rem 1rem` on nav links and `gap: 1rem` between header icons ([Ahmad Shadeed](https://ishadeed.com/article/target-size/)). Text over Safari's tinted chrome needs 4.5:1 contrast for body text and 3:1 for large text ([medienbaecker](https://medienbaecker.com/articles/the-web-behind-glass)). Set the viewport meta to `width=device-width, initial-scale=1, viewport-fit=cover` without `user-scalable=no`. Keep inputs at 16px so iOS does not zoom the Connect form, use `clamp(2.5rem, 11vw, 4.5rem)` for display type, size everything in rem, and add a landscape breakpoint at `(max-height: 500px) and (orientation: landscape)` instead of a rotate-your-phone blocker.

**Core Web Vitals are the scoreboard.** At the 75th percentile, the targets are LCP under 2.5 s, INP at or under 200ms and CLS under 0.1, and only about 48% of mobile pages pass against 56% on desktop ([corewebvitals.io](https://corewebvitals.io/core-web-vitals)). Make the HTML headline the LCP element, and do not fade it in from `opacity: 0` with JS. Keep initial JS around 150 to 170 KB gzipped, use one font family with two weights, and keep the LCP poster under 100 KB. Prefetch case-study routes when they scroll into view, not on hover (hover never fires on touch), which is also what makes the view-transition morph pair. Give every video, cover and diagram an explicit `aspect-ratio`. Measure field data with the `web-vitals` attribution build and lab-test on a real low-end Android phone.

## Conclusion

The headline shift is that the browser now does most of what this site's motion needs. Scroll timelines, view transitions and native snap replace the JS orchestration that once justified Lenis, ScrollTrigger and router hacks. The engineering effort that frees up is best spent where it shows judgment: a sphere that scrubs and degrades into a carousel, a chat that cites its sources and refuses to leak client detail, and diagrams that explain a supervisor-agent system without naming anything confidential. For a GenAI developer, the site's restraint and its working AI features are stronger evidence than any loop a model can generate, and the media plan should follow from that rather than the other way round.

Three uncertainties deserve a test pass before launch rather than trust. Firefox support for scroll-driven animations is newly on in 159 but was flagged off in 152 a few months earlier, so verify the `@supports` fallback in an older Firefox. iOS 26's fixed-element clipping has no Apple statement, so test the top bar and menu sheet with Safari's Compact, Bottom and Top tab layouts. Most of the numeric starting values here (sphere tiers, file-size budgets, observer bands, drag thresholds) are practitioner heuristics, not measured benchmarks, so treat them as defaults to tune against field Web Vitals once real traffic arrives.
